# C problem modeling workflow

Apply the stop-that-shit working rules to the lead agent, implementation agents and reviewers. Use the simplest method that meets the problem and the fixed specification. Add a diagnostic or branch when it resolves an identified data, modeling or delivery need.

Before any formal run, record changed estimands, assumptions, parameters, validation units and their rationale in docs/model-spec.md. Label prior exploratory runs. Keep primary choices fixed when interpreting results, and report the agreed sensitivities alongside them.

Use the existing reproduction entry point and publish the agreed milestones with links to their validation evidence.
